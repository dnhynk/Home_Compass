## 2. 기술문서 hwp 를 열었다

`아파트 전월세 실거래가 자료 기술문서.hwp` — 114,688 bytes, OLE 복합문서(`D0CF11E0A1B11AE1`).
`BodyText/Section0` 을 zlib(raw deflate)로 풀고 HWP 레코드 `HWPTAG_PARA_TEXT`(tag 67)의
UTF-16LE 문자열을 뽑았다.

> **`DERIVATION.md` 0절이 「원문 명세가 hwp 기술문서이고 열지 않았다」고 적어 둔 그 문서다.
> 이제 열렸다.** 이 절은 그 서술을 갱신할 근거가 된다(처리는 코디네이터의 판단이다).

### 2.6 이 hwp 를 어떻게 열었나 (재현 경로)

```python
# 1) 내려받기 — data.go.kr 의 다운로드 버튼 onclick 이 fn_fileDownload('FILE_...','1') 이다
httpx.get("https://www.data.go.kr/cmm/cmm/fileDownload.do",
          params={"atchFileId": "FILE_000000003687050", "fileSn": "1"}, follow_redirects=True)
# Content-Disposition: attachment; filename="아파트 전월세 실거래가 자료 기술문서.hwp"  (114688 bytes)

# 2) OLE 스트림 BodyText/Section0 을 raw deflate 로 풀고
#    HWP 레코드 헤더(4바이트: tag=하위10비트, size=상위12비트, 0xFFF면 다음 4바이트가 실제 크기)를
#    따라가며 tag==67(HWPTAG_PARA_TEXT)의 UTF-16LE 를 이어 붙인다.
#    제어문자 1,2,3,11,12,14~18,21~23 은 16바이트 확장 제어문자라 14바이트를 더 건너뛴다.
```

- `olefile` 이 환경에 없어 **scratchpad 안에만** `--target ./pylib` 로 받아 썼다.
  저장소에는 아무 의존성도 추가하지 않았다.
- 표의 셀 경계가 문자열에 남지 않으므로 위 표는 **읽은 순서대로 재조립한 것**이다.
  값 자체는 원문 그대로이고 지어낸 칸은 없다.

## 3. ★ 이 발췌가 확인하지 못한 것

1. **매매 엔드포인트(`RTMSDataSvcAptTrade`, 15126469)의 기술문서는 열지 않았다.**
   같은 방법으로 열릴 것으로 보이지만 **해 보지 않았다.**
2. **기술문서의 「서비스 이력」 칸이 비어 있다.** 2026-07-01 코드 변경이 이 API 에 언제
   반영됐는지는 문서가 말하지 않는다. 포털 화면의 「수정일 2026-07-29」가 유일한 날짜 단서인데,
   그것이 코드 변경 반영일인지는 **확인하지 못했다.**
3. **국토교통부·한국부동산원이 이 코드 변경을 이용자에게 공지했는지 찾지 않았다.**
   포털의 「데이터 개선요청 / 오류신고」 게시판도 열지 않았다.
