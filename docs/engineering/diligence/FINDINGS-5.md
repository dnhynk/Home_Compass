# 잔여 실사 결과 5차 — 광주(29xxx)가 실거래가 오픈API 에서 0건인 이유

- 작성: W-research-5
- 조회일: **2026-08-14** (표의 모든 행에 공통. 개별 행에 다른 날짜는 없다)
- 대상: `regions.json` 의 `29155` 한 행에서 시작한, **국토교통부 실거래가 오픈API 의 `LAWD_CD` 규약**.
- 취득 수단: **Orca 내장 브라우저** (`orca goto` · `eval`) 와 **실거래가 API 직접 호출**.
  값은 전부 렌더링이 끝난 뒤의 DOM 텍스트, 또는 응답 XML 을 직접 읽었다.
  **스크린샷도, 검색엔진 요약도 어떤 값의 근거로도 채택하지 않았다.**
  검색엔진은 후보 URL 을 찾는 데만 썼다.
- API 키는 저장소 밖 `.env` 에서 **읽기만** 했고 수정하지 않았다. 호출은 전부 조회(GET)다.
- **이 문서는 조사 결과일 뿐이며 처리 지시가 아니다.** 지역을 지울지 코드를 고칠지는
  코디네이터와 사용자의 판단이다. `regions.json` · `backend/` · `frontend/` · `contracts/` ·
  `scripts/` · `.env` 는 **한 줄도 건드리지 않았다.**

## 한 줄 결론

| | 결론 | 확신도 |
|---|---|---|
| **왜 0건인가** | **가설 A 다 — 우리가 쓰는 `LAWD_CD` 가 광주에 대해 틀렸다.** 다만 「처음부터 틀린 코드를 적었다」가 아니라 **「맞던 코드가 2026-07-01 에 폐지됐다」**다. 「전남광주통합특별시 설치를 위한 특별법」(법률 제21738호, 시행 2026-07-01)이 **전라남도와 광주광역시를 각각 폐지**했고, 광주 5개 자치구의 법정동코드가 **`29xxx` → `12xxx`** 로 전부 바뀌었다. # 2. 우리 데이터와 무엇이 다른가 — **결함이 두 겹이다**

`regions.json` 의 해당 행 (최초 커밋 `3f15372` 이후 바뀐 적 없다):

```json
{ "code": "29155", "name": "광주 광산구", "jeonseMedianKRW": 120000000, … ,
  "source": "프로토타입 예시 데이터" }
```

## 2.1 결함 ① — **이름과 코드가 어긋나 있다** (통합과 무관하다)

| | 우리 값 | 원문 | 차이 |
|---|---|---|---|
| `code` | `29155` | `29155` = **광주광역시 남구** (K2) | — |
| `name` | **「광주 광산구」** | 광산구는 **`29200`** (K3) | **이름과 코드가 다른 구를 가리킨다** |

**이 결함은 2026-07-01 통합과 아무 상관이 없다.** 저장소 최초 커밋부터 그랬고,
통합이 없었더라도 그대로였다.

**오차의 크기 — 이 실사가 계산한 참고값 (공표 통계가 아니다).**
만약 통합 전에 파이프라인이 돌았다면 「광산구」라는 이름 아래 **남구의 시세**가 채워졌을 것이다.
그 둘이 얼마나 다른지 재 봤다 — 저장소의 집계 조건(아파트 · 전용 85㎡ 이하 · 전세 · 계약월
3개월)을 그대로 걸고, 계약월 **202604·202605·202606**, 신규 코드로 호출:

| 지역 | 원자료 행 수 | 전세 · 85㎡ 이하 표본 | **전세 보증금 중앙값** |
|---|---|---|---|
| **남구** (12270 = 구 29155) | 633 | 283 | **200,000,000원** |
| **광산구** (12330 = 구 29200) | 1,913 | 969 | **218,900,000원** |

→ 광산구 자리에 남구 값이 들어가면 **전세 중앙값이 약 1,890만원(8.6%) 낮게** 들어간다.
**이 방향이 판정에 어떻게 작용하는지는 이 실사가 추적하지 않았다** — `risk`·지불능력 로직을
읽지 않았다. 다만 「지역 시세가 실제보다 낮게 들어간다」는 사실만 놓는다.

> ⚠️ 위 두 중앙값은 **우리가 계산한 값이며 어느 기관의 공표 통계도 아니다.**
> `regions.json` 에 옮겨 넣을 값으로 쓰라는 뜻이 아니다.

## 2.2 결함 ② — **코드 자체가 폐지됐다** (2026-07-01)

| | 우리 값 | 원문 | 차이 | **드러나는 방식** |
|---|---|---|---|---|
| `code` | `29155` | **2026-07-01 폐지** (K2·K4) | 현행 코드가 아니다 | **오류가 아니라 `totalCount=0`** (A1·A3) |

`pipeline.py` 는 표본이 `ingest.market_min_sample_count` 미만이면
`sample_shortage` 로 그 지역을 **건너뛰고 이전 값을 유지한다**(`pipeline.py:597`).
따라서 이 행은 앞으로도 **`source: "프로토타입 예시 데이터"` 인 채로 남는다.**

**그런데 그 실패 메시지는 「표본 부족 — 전세 0건 · 월세 0건」이다.**
「그 달에 거래가 적었다」와 **글자 그대로 같은 문장**이다.

> `source.py` 는 봉투(`response` vs `OpenAPI_ServiceResponse`)를 구분해 「조용한 0건」을
> 막아 두었다. **이 층위의 0건은 그 방어를 통과한다** — 봉투도 `resultCode` 도 정상이기
> 때문이다. `DERIVATION.md` 0절이 「조용한 0건을 만들지 않는 것이 이 설계의 이유다」라고
> 적은 그 위험이, **한 겹 아래에서 실제로 일어났다.**

## 2.3 부수 관찰 — **내 과업 범위 밖이므로 손대지 않았다**

- **인천에서도 같은 일이 진행 중이다.** `28110`(인천 중구) → 0 / `28185`(연수구) → 1038.
  행정표준코드 조회 `2811000000 \| 인천광역시 중구 \| **폐지**`. 시군구 목록에
  **제물포구(125) · 영종구(155) · 서해구(275) · 검단구(290)** 가 새로 있다.
  코드변경안내에 「2026.7.1 인천광역시 서해구 …」·「2026.7.1 인천광역시 중구, 인천광역시 동구 …」
  공지가 있다(K2 1절). **우리 `regions.json` 에 인천은 없다.**
- **`DERIVATION.md` 0절의 「응답 항목명은 2차출처까지만 확인됐다 — 원문 명세가 hwp 기술문서이고
  열지 않았다」는 서술이 이번에 낡았다.** hwp 를 열었고 항목 명세 전체와 「(만원)」 단위 표기를
  원문확인했다(D7 · K3 2.4). **문서 갱신은 하지 않았다** — 내 소유 경로가 아니다.

## 3.1 행정표준코드관리시스템 (K1~K8)

```
orca tab create --url "https://www.code.go.kr/stdcode/regCodeL.do" --json
```

- 시/도 = `id=Type1`(name `sidoCd`), 시/군/구 = `id=Type2`(name `sggCd`).
  **시군구는 ajax 로 채워지므로** `s.value="12"; s.dispatchEvent(new Event("change",{bubbles:true}))`
  로 직접 쏘고 약 1초 기다린 뒤 option 을 읽는다.
- 단건 조회는 폼에 넣고 사이트 핸들러를 부른다:
  `f.regionCd.value="2920000000"` · `disuseAt` 라디오를 `ALL` 로 · `func_search("10")`.
- ⚠️ 출력항목 체크박스에 **합성 `click` 이벤트를 쏘면 안 된다.** `checked` 가 도로 뒤집혀
  조회마다 폐지일 칸이 나왔다 안 나왔다 한다. `checked = true` 만 준다. (실제로 한 번 걸렸다)

## 3.2 법제처 (K10·K11)

친화 URL 이 조문 단위로 바로 열린다. **본문은 중첩 iframe 안에 있다:**

```
orca goto --url "https://www.law.go.kr/법령/전남광주통합특별시설치를위한특별법/제7조"
orca eval --expression '[...document.querySelectorAll("iframe")].map(f=>f.contentDocument&&f.contentDocument.body.innerText).join("")'
```

목록 화면(`lsSc.do`)에서 링크를 클릭해 들어가면 조문 본문이 **iframe 밖에서는 안 잡힌다.**
조문 친화 URL 로 직행하는 편이 확실하다.

## 3.3 기술문서 hwp 를 여는 법 (D1·D5·D7)

`data.go.kr` 다운로드 버튼의 `onclick` 이 `fn_fileDownload('FILE_000000003687050','1')` 이다.

```
GET https://www.data.go.kr/cmm/cmm/fileDownload.do?atchFileId=FILE_000000003687050&fileSn=1
```

받은 것은 OLE 복합문서(`D0CF11E0A1B11AE1`). `BodyText/Section0` 을 **raw deflate**(`zlib.decompress(raw, -15)`)로
풀고 HWP 레코드를 따라가며 `tag == 67`(HWPTAG_PARA_TEXT)의 UTF-16LE 를 이어 붙이면 본문이 나온다.
상세는 [`K3`](excerpts/K3-공공데이터포털-LAWD_CD-규약과-기술문서.md) 2.6.

## 3.4 새 코드를 어떻게 찾았나 (A군)

**가설을 세우기 전에 먼저 훑었다.** 접두 `10`~`99` × 접미 `110`·`111` 을 202512 로 전부 호출해
「알려진 시도가 아닌데 자료가 있는 코드」 하나(`12110`)를 찾고, 그 응답의
`aptSeq=46110-98` · `umdNm=상동` 에서 접두 `12` 를 잡았다.
그 **뒤에** 행정표준코드에서 원문으로 확인했다. 순서를 [`K4`](excerpts/K4-실호출-관측기록.md) A10 에 남겼다.

## 3.5 ⚠️ 표준출력 인코딩

`orca ... --json` 을 파이프로 바로 읽으면 콘솔 코덱에 걸려 한글이 깨진다.
**파일로 받아 UTF-8 로 파싱**해야 한다 (`FINDINGS-4.md` 3.5 와 같다).
`python -c` 안에서 소스 파일을 읽을 때도 `encoding="utf-8"` 을 명시해야 한다 —
기본 코덱이 `cp949` 라 한글이 든 파일에서 터진다. 실제로 한 번 터졌다.

   **그것이 코드 변경 반영일인지 확인하지 못했다.** 「데이터 개선요청 / 오류신고」 게시판도
   열지 않았다. → **이 변경이 언제부터 API 에 반영됐는지는 모른다.**
7. **국토교통부 실거래가 공개시스템(rt.molit.go.kr)의 지역 선택 화면을 확인하지 못했다.**
   `https://rt.molit.go.kr/` 은 열렸으나(`document.title` = 「국토교통부 실거래가공개시스템」)
   **지역 선택 상자가 DOM 에 없었다** — SPA 이고 하위 화면(`/pt/xls/xls.do`)으로 이동하니
   브라우저 탭이 닫혔다(`browser_no_tab`). **시민이 보는 화면에서 광주가 어떤 이름으로
   나오는지 보지 못했다.**
8. **한국부동산원의 별도 공표 통계(R-ONE 등)를 확인하지 않았다.**
   다만 이 API 의 **운영 주체가 한국부동산원**임은 원문확인했다(D6).
9. **다른 시도의 코드가 앞으로 언제 또 바뀔지 알아보지 않았다.**
   확인한 것은 「강원(42→51)·전북(45→52)에 선례가 있고(A10), 인천이 지금 바뀌는 중이다(2.3)」까지다.
   **행정표준코드의 예고된 변경 목록을 조회하지 않았다.**
10. **`aptSeq` 의 앞 5자리가 「구 시군구코드」라는 것은 기술문서가 명시하지 않는다.**
    문서가 적은 것은 「단지 일련번호 / 샘플 `11110-34`」까지다(D7). 우리가 관측한 대응
    (12270↔29155, 12330↔29200, 12110↔46110 …)은 **일관되지만 원문의 진술은 아니다.**
    다만 **신·구 대응의 근거는 `aptSeq` 가 아니라 행정표준코드 원문(K1~K7)이며**,
    `aptSeq` 는 그것을 뒷받침하는 관측일 뿐이다.
11. **판정 로직에 대한 영향을 추적하지 않았다.** 2.1 의 「전세 중앙값이 8.6% 낮게 들어간다」가
    `risk`·지불능력 판정에서 어느 방향으로 작용하는지 **코드를 읽지 않았다.**

# 6. 코디네이터에게 넘기는 판단 재료 — **여기서 결정하지 않는다**

처리는 내 결정이 아니다. 판단에 필요한 사실만 정리한다.

**사실 정리**

1. `29155` 는 **남구**이고 우리 이름표는 **광산구**다. **둘 다 폐지된 코드다.**
2. 광주 광산구의 현행 코드는 **`12330`** 이고, 그 코드로 부르면 자료가 **2011년까지** 나온다.
3. 광주 5개 자치구 전체의 현행 코드는 **12210 동구 · 12240 서구 · 12270 남구 · 12300 북구 ·
   12330 광산구**다.
4. 「이름을 고칠 것인가 코드를 고칠 것인가」는 **원문이 답할 수 있는 질문이 아니다.**
   최초 커밋의 의도가 광산구였는지 남구였는지 기록이 없다.

**제안 (결정이 아니다)**

- 코드만 갱신하면 **결함 ①이 그대로 남는다.** `29155 → 12270` 은 「남구」를 「광산구」라는
  이름으로 채우게 되고, 지금까지 숨어 있던 오차가 **비로소 실측값으로 실현된다.**
  이름과 코드 중 **무엇을 정본으로 볼지 먼저 정해야** 갱신 방향이 정해진다.
- 지역을 지우는 것은 **자료 부재를 이유로 삼을 수 없다.** 자료는 있다(A4).
- **광주 한 건만 고치면 같은 유형이 다시 온다.** 강원·전북에 선례가 있었고(A10),
  인천이 지금 바뀌는 중이다(2.3). 다만 「그래서 무엇을 해야 하는가」는 내 몫이 아니다.
- **`totalCount=0` 이 「모르는 코드」와 「거래 없음」을 구분하지 못한다**(A3)는 것은
  이 한 지역의 문제가 아니라 **수집 계층 전체의 관측 한계**다. `source.py` 가 이미
  봉투 단위로 조용한 0건을 막고 있으므로, 그 방어를 어느 층위까지 밀지는 설계 결정이다.

**두 건 공통** — 이 문서의 어떤 값도 `regions.json` 에 그대로 옮겨 넣을 수 있는 형태가 아니다.
특히 2.1 의 두 중앙값은 **이 실사가 계산한 참고값이며 공표 통계가 아니다.**
