## A3. ★ **존재하지 않는 코드도 `totalCount=0` 이다** — 0 은 구분되지 않는다

| LAWD_CD | 결과 |
|---|---|
| `99999` (아무 데도 아님) | HTTP 200 · `resultCode=000` · `resultMsg=OK` · **`totalCount=0`** |
| `29000` (시도 5자리 흉내) | 같음 · 0 |
| `2911` (4자리) | 같음 · 0 |
| `291100` (6자리) | 같음 · 0 |

**기술문서에 `03 No Data` 코드가 있는데도(K3 2.5) 오지 않는다.**
즉 이 API 에서 `totalCount=0` 은 세 가지를 한 덩어리로 뭉갠다 —
① 그 달에 거래가 없었다 ② 그 코드는 이 API 가 모르는 코드다 ③ 파라미터가 애초에 틀렸다.

> `source.py` 가 봉투(`response` vs `OpenAPI_ServiceResponse`)를 구분해 「조용한 0건」을
> 막아 두었지만, **이 층위의 0건은 그 방어를 통과한다.** 봉투도 정상이고 `resultCode` 도
> 정상이기 때문이다. 이것은 관측이고, 처리 방안은 내 몫이 아니다.

## A10. 새 시도 접두 두 자리를 어떻게 찾았나 (탐색 경로)

가설을 세우기 전에 **먼저 훑었다.**

1. `53xxx`~`57xxx` × 흔한 접미 8종 → 전부 0. (「신설 시도는 52 다음 번호」라는 짐작은 틀렸다)
2. 접두 `10`~`99` 전체 × 접미 `110`·`111`, 202512 → 자료가 있는 것 13건.
   그중 **알려진 시도가 아닌 것이 `12110`(328건) 하나**였다.
3. `12110` 의 첫 항목: `aptSeq=46110-98` · `umdNm=상동` · `roadnm=백년대로337번길 23`
   → **구 46110 목포시**. 여기서 접두 `12` 를 잡았다.
4. `12000`~`12995` 를 5단위로 훑어 25건을 얻고 `aptSeq` 로 신·구를 짝지었다(A6).
5. 그 뒤에 행정표준코드관리시스템에서 **원문으로 확인**했다(K1).

★ **순서를 밝혀 둔다.** 접두 `12` 는 API 를 훑어서 **먼저 추측**했고, 그 추측을 원문이
**나중에 확인**했다. 문서 1절의 값들은 전부 원문(K1) 쪽이 근거이며, 이 스캔은 근거가 아니라
원문을 어디서 찾을지 정한 수단이다.

## 재현 방법

```python
import httpx
from xml.etree import ElementTree
r = httpx.get("https://apis.data.go.kr/1613000/RTMSDataSvcAptRent/getRTMSDataSvcAptRent",
              params={"serviceKey": KEY, "LAWD_CD": "12330", "DEAL_YMD": "202512",
                      "numOfRows": "1", "pageNo": "1"}, timeout=30.0)
root = ElementTree.fromstring(r.text)
root.find(".//totalCount").text          # -> '815'
{c.tag: c.text for c in next(root.iter("item"))}   # aptSeq -> '29200-139'
```

키는 `.env` 의 `MOLIT_API_KEY`. `%` 가 들어 있으면 `urllib.parse.unquote` 로 한 번 풀어야
한다 — 그러지 않으면 이중 인코딩되어 「등록되지 않은 서비스키」로 거절된다
(저장소 `source.py`의 `normalise_service_key` 가 하는 일과 같다).
