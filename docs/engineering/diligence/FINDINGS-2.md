## 이 문서를 읽는 법

**추정·외삽·기억으로 채운 값은 이 문서에 하나도 없다.** 못 찾은 것은 4절에 따로 모았다.

### 취득 방법에 관한 고지

- 모든 수치는 **JS 렌더링이 끝난 뒤의 DOM 텍스트**(`document.body.innerText` 또는 표 셀의
  `innerText`)를 직접 읽었다. **스크린샷도, 요약 모델의 출력도 근거로 채택하지 않았다.**
- HTML `<table>` 에서 읽은 값은 셀 인덱스가 곧 열이므로 열이 뒤섞일 여지가 없다.
- PDF 에서 읽은 값(R5)은 추출기가 열을 뒤섞을 수 있으므로, **본문 서술의 증감 진술과
  산술 대조해 열 대응을 검증**했다 (`excerpts/R5-...md` 5절).
- R4 는 값을 새로 읽은 것이 아니라 **통계표 ID 를 확정**한 건인데,
  `FINDINGS.md` A2-1·A2-2 가 보도자료에서 읽은 값 **8개가 그 통계표에서 그대로 재현되는 것**을 확인했다.

# 2. 각 항목의 도달 경로 — 다음 사람이 같은 길로 다시 오게

**이 값들은 주기적으로 갱신된다.** 아래는 재현 절차이며, 화면 인용문 전문은 `excerpts/` 에 있다.
ref(`@e44` 같은 것)는 스냅샷마다 바뀌므로 **이름으로 찾아 다시 잡아야 한다.**

## 2.1 R1 — KOFR

```
orca tab create --url "https://www.kofr.kr/rate/rateStatistics.jsp" --json
# 렌더링 대기 약 10초. 클릭·프레임 진입 불필요
orca eval --expression 'document.body.innerText' --json
```

**앞 조사가 실패한 이유:** HTTP 로 받은 HTML 3,434바이트에는 표가 없다. WebSquare 가 JS 로 그린다.
브라우저로 열면 **최상위 문서 innerText 에 표가 그대로 나온다.** 별도 API 도 프레임도 필요 없었다.

## 2.2 R2 — 국고채 5년

```
# 루트는 <frameset> 이다. 최상위 문서 innerText 는 빈 문자열
orca goto --url "https://www.kofiabond.or.kr/html/MAIN.html" --json
#   → https://www.kofiabond.or.kr/websquare/websquare.html?w2xPath=/xml/main.xml 로 리다이렉트
# 렌더링 대기 약 12초
orca snapshot --json                       # role=tab, name="최종호가수익률" 의 ref 확보
orca click --element "@<그 ref>" --json
orca eval --expression 'document.body.innerText' --json
```

**앞 조사가 실패한 이유는 두 겹이다.** (1) 루트가 프레임셋이라 최상위에 본문이 없다.
(2) 본문 프레임에 들어가도 **기본 탭이 「지수」**여서 금리표가 렌더링되지 않는다.

## 2.3 R3 · R4 — KOSIS 통계표 (공통 절차)

```
orca goto --url "https://kosis.kr/statHtml/statHtml.do?orgId=<orgId>&tblId=<tblId>" --json
# 주소창은 ...statHtml.do?sso=ok&returnurl=... 로 보이지만 document.title 은 통계표명이다. 이 화면이 맞다
# 좌측 트리(iframe_leftMenu) 렌더링 대기 약 25초
orca snapshot --json                       # 트리에서 통계표명 링크의 ref 확보
orca click --element "@<그 ref>" --json     # ← 이걸 해야 그리드가 생성된다
# 그리드 로딩 대기 약 30초
orca eval --expression '
  var d = document.getElementById("iframe_rightMenu").contentDocument
            .getElementById("iframe_centerMenu2").contentDocument;
  /* d.getElementById("mainTable") = 데이터, d.getElementById("mainTableT") = 머리글 */ ' --json
```

**앞 조사의 「302 → sso.kosis.kr」 실패 원인:** HTTP 클라이언트가 SSO 왕복을 끝내지 못한 것이다.
브라우저는 왕복을 마치고 통계표 화면으로 돌아온다. **로그인은 필요 없었다.**

> **함정.** 그리드 iframe 의 src(`statHtmlContent.do?...`)를 **단독 탭으로 열면 `#mainTable` 이 비어 있다.**
> 반드시 부모 프레임을 거쳐 트리를 클릭해야 데이터가 채워진다.

통계표 ID 를 모를 때의 탐색 경로:

```
orca goto --url "https://kosis.kr/search/search.do?query=<통계표명>" --json
# 결과 앵커의 onclick 에 generator_link('<orgId>','<tblId>', ...) 가 들어 있다
```

## 2.4 R5 — 주거실태조사 연구보고서 PDF

```
orca goto --url "https://stat.molit.go.kr/portal/cate/statMetaView.do?hRsId=327" --json
```

내려받기는 GET 이다 (페이지의 `downFile()` 함수에서 확인):

```

  ?oFileName=<파일명 URL인코딩>&rFileName=<같은 값>&midpath=%2Fstat_file%2F
```

- **헛다리:** `2024년도 주거실태조사_통계보고서_최종(2026.01.07기준).pdf` (546면) 에는
  `RIR`·`월소득`·`임대료 비율` 문자열이 **0건**이다. 통계보고서는 원표 집계집이고 RIR 은 파생지표다.

## 4.2 R1 — 「일자」 열의 뜻을 원문으로 확정하지 못했다

통계표의 `일자` 열이 **기초거래일**인지 **공시일**인지 페이지에 명시가 없다.
사이트는 「공시일 전영업일 거래를 기초로 공시일 당일 산출, 매일 오전 11시 공시」라고만 적는다.

조회 시각(2026-08-13 22시대, 당일 11시 공시가 이미 끝난 시점)에 `20260813` 행이 없고
`20260812` 가 최신인 것은 **기초거래일 표기와 정합**하지만, **이는 관찰에 근거한 추론이지 원문 진술이 아니다.**
`observed_at` 은 **원문에 찍힌 일자 그대로** `2026-08-12` 로 적었다.

## 4.3 R5 — `observed_at` 을 2024-01-01 로 둔 것은 **재검토 대상이다**

`FINDINGS.md` 6.5 는 「주거실태조사의 조사 실시기간을 확인하지 못해 `observed_at` 을 조사연도
시작일(2024-01-01)로 두었다」고 적었다. **이번에 조사기간이 확인됐다.**

국토교통 통계누리 통계정보 (https://stat.molit.go.kr/portal/cate/statMetaView.do?hRsId=327) 원문:

```
작성(조사)주기  매년          작성(조사)기간  조사년도 7~12월
공표시점        익년 하반기   공표방법        보도자료, 보고서 및 국토교통통계누리
작성(조사)근거  승인번호 제 116031호 2006-08-11 / 주거기본법 제20조 및 같은법 시행령 제13조
```

연구보고서 p.54 원문:

```
주 : 「2024년도 주거실태조사」의 소득은 세금 등을 제외한 월평균 실수령액
     (2023년 1월∼12월까지의 월평균 금액)을 조사한 결과이며, 통계청 가계동향조사와는 차이가 있음
```

> **코디네이터 판단 필요.** 조사는 **2024년 7~12월**에 실시됐고, 소득은 **2023년 1~12월 월평균**을
> 물었다. 즉 `2024-01-01` 은 조사 실시기간도 소득 참조기간도 아니다.
> 이 문서는 `FINDINGS.md` 와의 일관성을 위해 일단 `2024-01-01T00:00:00+09:00` 로 적었으나,
> **A5 계열 7행 전부에 대해 `observed_at` 규약을 다시 정할 필요가 있다.** 나는 지어내지 않았고,
> 확인된 사실만 위에 옮겼다.

## 4.4 R5 — 「3배 이상 격차」 서술은 이 데이터에서 재현되지 않는다

`FINDINGS.md` 2절이 코디네이터에게 넘긴 물음의 답이다. 2024년 **중위수** 기준:

```
일반(전체) 15.8  ·  청년 16.0  ·  소득 하위 18.3  ·  소득 중위 16.2  ·  소득 상위 19.4
```

**최대·최소 비는 19.4 / 15.8 ≈ 1.23배다.** 어느 두 모집단을 잡아도 3배가 되지 않는다.
평균 기준으로 넓혀도 24.1 / 20.2 ≈ 1.19배다.

> **코디네이터 판단 필요.** SPEC Part 0-C 의 「청년 RIR 이 일반 임차가구 기준과 저소득층 기준
> 사이에서 3배 이상 벌어진다」는 서술은 **2024년도 주거실태조사에서 근거를 찾을 수 없다.**
> `FINDINGS.md` 가 「저소득층 RIR 이 비어 있어 확정할 수 없다」고 유보했던 부분인데,
> 그 칸이 채워진 지금 **서술 자체가 재검토 대상이다.**

## 4.5 R5 — 우리 지표와 분모가 같다 (`FINDINGS.md` 5절 보강)

주거실태조사 RIR 의 분모는 **「세금 등을 제외한 월평균 실수령액」**이다 (연구보고서 p.54).
우리 `affordability.housing_cost_ratio_cap` 의 분모(월 실수령액)와 **정의가 같다.**

이는 `FINDINGS.md` 5절이 DSR(분모 = 세전 연소득)을 준거로 쓸 수 없다고 결론낸 것과 대비된다.
**RIR 은 분모 정의가 우리와 일치하므로 준거로 쓸 수 있다.** 다만 분자(월임대료)는
보증금을 월세이율로 환산한 값이므로 우리 `monthlyHousingCost` 정의와 같은지는 확인하지 않았다.
