## 0. ★★ 우리가 저작물에 하는 일 — 「학습」이라고 쓰지 않는다

이용조건 판정·심사 답변·협의 문안 어디에도 「학습」이라는 표현을 쓰지 않는다. 사실이 아니다.

| | 사실 |
|---|---|
| 하는 것 | **원문 텍스트를 LLM 에 입력해 판정 규칙으로 구조화 추출**한다. 출력은 `RuleDraft` 이고, 인용 구간(span)이 원문에 실재하는지 기계가 대조한다 (SPEC 4.2) |
| 하지 않는 것 | **모델 학습·가중치 갱신이 없다.** 학습용 데이터셋을 만들지도, 재판매하지도 않는다 |

**따라서 공공누리 AI유형의 적용 대상이 아니다.** AI유형 원문(`diligence/excerpts/R6-공공누리-AI유형.md`):

> 이용자는 AI유형이 표시된 공공저작물을 '인공지능 학습용 데이터'로 이용할 목적이 아닌 경우
> 함께 표시된 기존 공공누리 유형의 이용조건을 준수하여야 합니다.

→ 우리는 **기존 유형(제1~4유형)의 이용조건으로 판정받는다.** 6절이 확인한 것이 그 유형이다.
앞 판본은 이 결론을 「AI유형 마크가 부착돼 있지 않으므로」로만 적었는데, 그것은 근거의 절반이다.
**설령 부착돼 있었더라도** 우리 처리는 AI유형의 적용 대상이 아니다.

## 2. ★ 크기 실측 — 결론: **분할 설계는 만들지 않는다**

NFC 정규화 후 **유니코드 코드포인트** 수다. 바이트도 UTF-16 코드유닛도 아니다 (SPEC 4.2.1).

| | 값 |
|---|---|
| 최대 (`seoul_youth_rent`) | **12,248** |
| 최소 (`youth_rent_support`) | **2,691** |
| 확보 8건 합계 | **56,758** |

사용자 결정은 「통째로 넣는 것이 기본, 분할은 초과 시만」이었고, 코디네이터가 이 실측치를 보고
**분할 불필요**로 결론했다 (2026-08-14). SPEC 4.2 는 이 전제로 설계한다 —
「쓰지 않는 표현력은 검증 불가능한 표면만 늘린다」(4.2.3)에 부합한다.

> **정정.** 워커가 중간보고에서 합계를 56,757 · `youth_rent_support` 를 2,690 으로 보고했으나
> **정확한 값은 56,758 · 2,691** 이다. 그 파일에 CRLF 가 1개 있어 파이썬 `Path.read_text()` 의
> 보편 개행 번역이 `\r\n` 을 `\n` 으로 접었던 것이다. 정본은 번역하지 않은 2,691 이며
> (`read_bytes().decode()`), 6절에 이 문제의 처리를 적었다. 1자 차이이고 결론은 바뀌지 않는다.

### 4.5 텍스트 추출 방법 — ★ 추출기가 바뀌면 span 오프셋이 어긋난다

| 형식 | 방법 |
|---|---|
| HTML | `document.body.innerText` **전체**. 사이트 네비게이션·푸터가 포함된다 |
| PDF | **PyMuPDF 1.27.2.3 / MuPDF 1.27.2** 의 `page.get_text()` 를 페이지 순서대로 `\n` 으로 연결 |

- **HTML 은 본문 선택자를 쓰지 않았다.** 기관마다 마크업이 달라 선택자를 10개 검증할 수 없고,
  선택자가 본문 일부를 **떨어뜨리는 실패**는 복구가 불가능한 반면 군더더기가 남는 실패는 아니다.
  대신 `body` 전체라는 **단일·무판단 규칙**을 썼다. 대가로 코드포인트 수에 사이트 공통 문구가
  약 1,200자 포함된다
  > ⚠️ 2단계 주의 — 좌측 메뉴에 **다른 상품명**이 들어 있다. LLM 이 사이드바에서 span 을
  > 잡을 수 있다. span 검증이 잡아내지만 프롬프트에서 먼저 막는 편이 낫다
- **PDF 추출기 비교를 실제로 했다.** pypdf 6.11.0 은 줄바꿈을 잃어 문장이 붙는다
  (⑥ 기준 12,444자, 행 구조 소실). PyMuPDF 는 행 구조를 유지한다(12,248자). 후자를 채택했다
- ★ `pypdf`·`PyMuPDF` 는 **수집 시점에만** 쓴 도구이며 `requirements.txt` 에 넣지 않았다.
  SPEC 4.1 이 「원본 파일을 다시 파싱하는 경로를 만들지 않는다」고 못 박았기 때문이다 —
  적재 경로(`ingest/loader.py`)는 `.txt` 만 읽는다

### 5.0 ★★★ 두 집합이 정확히 겹쳤었다 — **그 겹침이 결정 #15 로 풀렸다**

코디네이터 확인 요청(2026-08-14)에 대한 답이었고, **2차 판본까지는 이랬다:**

[실제 공고문 2건]     = seoul_youth_rent · seoul_deposit_interest
[당시 미적재 2건]     = seoul_youth_rent · seoul_deposit_interest   ← 같은 둘
```

「공고문 → 규칙 추출」의 입력이 저장소에 **0건**이었다.

> ### ✅ 3차 — **공고문 입력이 0건에서 2건이 됐다**
>
> 계약 결정 #15 가 제4유형 조건을 판단하면서 그 둘이 열렸다. 적재 7건의 구성은 이렇다:
>
> | 문서종류 | 적재 |
> |---|---|
> | **★ 실제 공고문** (`notice`) | **2** — ⑥⑧ 서울시 |
> | 상품안내 (`product_page`) | 5 — ①③④⑨⑩ |
>
> ★ 그래도 **공고문 입력은 2건까지다.** 나머지 6건은 이용조건으로 해결되지 않는다 —
> 5.1 · 5.2 가 그 이유이며 그것은 **제도의 형태**다. 2단계 범위 문제는 그대로 남는다.

> ### ⚠️ 정정 — 앞 판본이 이 겹침에 붙인 **설명은 틀렸다**
>
> 앞 판본은 이렇게 적었다:
>
> > 우연이 아니라 **구조**다. … **자유이용을 명시한 주체**는 중앙기관뿐이다.
> > 서울시는 공공누리 **미부착** 자료에 사전 협의를 요구한다
>
> **전제가 사실과 다르다. 서울시 공고문 2건은 공공누리가 부착돼 있다** (제4유형, 6.2).
> 「지자체는 개방하지 않는다」는 서술은 성립하지 않는다 — 지자체도 개방하며,
> 다만 **조건이 붙은 유형**(상업적 이용금지·변경금지)으로 개방한다.
>

### 5.1 주택도시기금 대출조건 — 근거 규정이 **비공개 시행세칙에 위임**한다

0건**이다. 구체적 대출조건이 규정에 없다. 규정 스스로 어디에 있는지를 밝힌다:

> — 「주택도시기금 운용 및 관리규정」 [시행 2024. 12. 6.] [국토교통부훈령 제1830호,

```

|---|---|---|

#### ✅ 판단이 왔다 — 계약 결정 #15 (사용자, 2026-08-14)

  (`contracts/**` 를 `eol=lf` 로 고정한 PR #12 와 같은 종류의 사고).
  `backend/tests/ingest/test_manifest.py` 가 `git check-attr` 로 속성 자체를 검사한다

### 7.1 ✅ `PolicySource` 의 `source_kind` 미결 — **닫혔다. 「정하지 않는다」가 답이다**

2차 판본이 이렇게 올렸다: 「①③④⑨⑩ 상품안내 5건은 SPEC 2.1 의 네 분류

**코디네이터 답(2026-08-14): 분류를 못 고른 것이 아니라 그 축을 적용할 대상이 아니라는
신호였다.**

| | `Provenance` 가 묻는 것 | `PolicySource` 는 |
|---|---|---|
| `source_kind` | 법정/통계/시장/규범 — **이 숫자가 어디서 왔는가** | 숫자가 아니다 |
| `verification` | 얼마나 믿을 만한가 | 참도 거짓도 아니다 |
| `observed_at` | 언제 기준인가 (신선도) | 등급을 매길 대상이 아니다 |

`Provenance` 는 **판정에 쓰인 사실**을 서술한다. `PolicySource` 는 사실이 아니라
**원자료**다. 그래서 **`PolicySource` 에 `Provenance` 를 붙이지 않는다** —
SPEC 2.2 가 이 엔티티에만 `Provenance` 를 주지 않은 것은 누락이 아니라 설계다.
계보는 그 원문에서 **추출된 규칙**(`RuleVersion`)이 지며, 거기서는 `source_kind` 가
`statute` 로 명확하다.

> 그래도 남는 사실은 남긴다 — draft 가 승인돼 `RuleVersion` 이 생길 때의 재료다.

## 8. ★★ 출처표시 — 계약 결정 #15 의 **유일하게 남는 의무**

결정 #15 는 이 의무를 문서에 적는 것으로 끝내지 말라고 못 박았다:

> `PolicySource.provenance` 의 `source_name`·`source_ref` 에 **기관 · 공고번호 · URL ·
> 공공누리 유형**이 들어간다 / 그 출처가 **화면까지 전달**되어야 한다 /
> **전달되는지를 테스트로 고정한다. 계보가 끊기면 출처표시 의무가 문서에만 남는다**

### 8.1 `PolicySource.provenance` 는 **없는 필드였다** — 그래서 `attribution` 을 더했다

`store/models.py` 의 `PolicySource` 는 `id · text · source_ref · fetched_at` 4필드였고
`Provenance` 를 갖지 않는다(7.1). 결정 #15 가 지목한 자리가 존재하지 않았으므로
코디네이터에게 올렸고, 답이 왔다 — **필드 하나를 더한다.**

```python
class PolicySource:
    id: str
    text: str
    source_ref: str | None      # 참조. URL 그대로 둔다
    fetched_at: datetime
    attribution: str | None     # ← 추가. 출처표시 문구
```

**기각한 안 — 「`source_ref` 한 필드에 네 요소를 말아 넣는다」.** 워커가 올린 안이고
코디네이터가 대가를 받지 않았다. `source_ref` 에 기관·공고번호·유형을 문자열로 말아 넣으면
**화면이 URL 만 뽑아내지 못하고 필드 이름이 내용과 어긋난다.**

`attribution` 은 `Provenance` 객체가 **아니다.** 그래서 `source_kind` 를 정할 필요가 없고,
7.1 의 미결을 되살리지 않는다.

### 8.2 형식 — **7건 전부 같다.** 갈래는 이용근거가 가른다

```
source_ref  = {URL}
attribution = {기관} 「{저작물명}」 ({공고번호} 또는 문서종류) · {이용근거}
```

네 요소는 **두 칸에 나뉘어** 산다 — 기관·공고번호·이용근거는 `attribution`, **URL 은
`source_ref`** 다. 둘은 같은 `PolicySource` 에 함께 실려 다니며 화면이 둘을 붙여 인용한다.

| 갈래 | 건수 | 이용근거 문자열 |
|---|---|---|
| 공공누리 제4유형 | **2** (⑥⑧) | `공공누리 제4유형(출처표시+상업적이용금지+변경금지)` |
| 저작권법 자유이용 | **5** (①③④⑨⑩) | `저작권법 제24조의2` |

★ **자유이용 5건에도 출처표시는 필요하다.** 근거가 공공누리가 아니라 저작권법 24조의2 일
뿐이다. 형식을 7건 공통으로 쓰되 **지켜야 할 조건이 다르다는 사실은 계보에서 구분된다** —
나중에 조건별로 다르게 다뤄야 할 때 계보만 보고 갈래를 나눌 수 있다.

실제로 저장된 값(실기동 8절 출력 그대로):

```
서울특별시 주택정책과 「2026년 서울시 청년월세지원 모집 공고」
  (서울특별시 공고 제2026-1440호) · 공공누리 제4유형(출처표시+상업적이용금지+변경금지)
  ↳ source_ref = https://www.seoul.go.kr/news/news_notice.do?bbsNo=277&nttNo=457234

국토교통부 주택도시기금 (포털 운영: 주택도시보증공사) 「청년전용 버팀목전세자금 > 대출안내」
  (상품안내) · 저작권법 제24조의2
  ↳ source_ref = https://nhuf.molit.go.kr/FP/FP05/FP0502/FP05020301.jsp
```

세 가지를 판단으로 적어 둔다:

1. **공고번호는 원문 표기 그대로다.** ⑧ 의 번호는 붙임표가 아니라 **EN DASH(U+2013)**
   (`서울특별시공고 제2026–1552호`)인데 ASCII 로 고쳐 쓰지 않았다. 출처표시는 원문이 쓴
   이름을 인용하는 것이다
2. **공고문이 아닌 문서에는 공고번호 자리에 문서종류**(`상품안내` 등)가 들어간다.
   빈 괄호로 두면 **받은 것이 무엇인지**가 사라진다 (5절의 구분이 여기서도 걸린다)
3. **이용근거는 `licence_basis` 칸에만 둔다.** 대장 표기용 `kogl_type` 에는 마크다운
   강조(`**제4유형**`)가 섞여 있어 화면이 그대로 인용할 수 없다. 문자열을 깎아 만들면
   대장의 표기를 바꿀 때마다 출처표시가 함께 움직인다

### 8.3 기관 표기 — 관측으로 닫았다

2차 판본은 코드가 `청년주거과`, 문서가 `주택정책과` 로 **갈라져 있었다**(9.1 #17).
출처표시에 그대로 인용되는 값이므로 관측으로 닫았다 — `www.seoul.go.kr` 고시·공고 상세의
「담당부서」 칸이 두 건 모두 **서울시 주택정책과**다 (⑥ 02-2133-7704 · ⑧ 02-2133-7277,
2026-08-14 원문확인). 조직도상 어느 쪽이 맞는지가 아니라 **그 공고문이 스스로 밝힌
담당부서**가 출처표시의 근거다.
